**Two standing metric rulings (Sep 16 2026):**

## 1. How the CoS actually runs

- **Scheduled sessions.** The CoS is instantiated by scheduled tasks (see §6). Each run is a fresh session that reads `/LANE-RULES.md` (STEP 0, from a fresh clone), then this charter, `claude/cos/STATE.md`, and the room docs, then works.
- **Agents are spawned per run.** Agents don't persist between runs; the CoS spawns them as subagents from the roster in §2B, gives each its room doc and a task, and synthesizes. New agent types are added to §2 by the CoS when a recurring need appears; obsolete ones are retired. Every roster change is logged in STATE.md under "Roster changes log".
- **Rooms are project docs** under `claude/rooms/`. Agents' dated entries (findings, decisions, questions for other agents) go in the room; the CoS reads all rooms at the start of a run, answers questions across rooms, and prunes each room to the last 30 days plus a pinned "standing decisions" block at the top. A room is created when two or more agents keep needing each other's output, and merged/closed when it goes quiet for a month. **Rooms as of Oct 1 2026: `site-quality` (absorbed `terminal`), `cards-and-data`, `growth`.** **Writing rule (Oct 1):** a Project write replaces a room whole, so the run that spawned the agents (usually the Wednesday weekly) writes each agent's entry into its room itself — read the room, add the entries under its Log, write it back, in the same run. No side files like `rooms/entries-<date>.md`.
- **Memory across runs** = STATE.md (current scores, open items, last run, what changed) + `claude/cos/NEEDS-MO.md` (the open queue for Mo) + the rooms.
- **Doctrine does not live in prompts (Sep 16).** Anything that must bind every lane goes in `/LANE-RULES.md`, in git, where it changes the day the rule changes. A lane that finds its prompt contradicting that file follows the file and reports the prompt as drifted.
